# Controller protocol v1

Transport-independent compact JSON text frames. Wi-Fi and USB tethering use identical WebSocket frames. Future Bluetooth framing must preserve message semantics.

## Pair before input

Client sends `{ "type":"pair", "version":1, "deviceId":"stable-local-device-id", "pin":"temporary-six-digit-pin" }` as its first frame. PIN is generated by the native PC using OS-seeded randomness, expires after 120 seconds, and is not stored by the browser. Native checks origin, ID, version and PIN. `paired` replies contain version, PC name and `virtualGamepad`. Linux sends `virtualGamepad:true` only after uinput creation. Failed pairing/uinput replies are `{ "type":"error", "message":"..." }` and close the session.

## Snapshot

```json
{
  "type": "input",
  "version": 1,
  "deviceId": "phone-id",
  "sequence": 1,
  "timestamp": 0,
  "left": [0, 0],
  "right": [0, 0],
  "l2": 0,
  "r2": 0,
  "buttons": [],
  "dpad": [0, 0],
  "touch": { "active": false, "x": 0, "y": 0 }
}
```

- `sequence`: strictly increasing per session; stale/duplicate packets are rejected.
- `timestamp`: finite nonnegative epoch milliseconds. Not used as a trust or clock-sync mechanism.
- Sticks: finite values −1 to 1, negative Y is up. Circular clamp, dead zone, sensitivity, response curve, inversion and stick swap are applied before serialization.
- Triggers: 0 to 1. Browser sliders represent position, not physical pressure or adaptive resistance.
- `buttons`: active names in `BUTTONS`, at most 12. Complete state rather than events so release cannot depend on a prior packet.
- D-pad: each axis exactly −1, 0 or 1. Up is Y=−1.
- Touch: active and normalized 0–1 coordinates. Linux currently maps click only to BTN_TRIGGER_HAPPY1; coordinate-based game touchpad behavior is not implemented.
- Optional gyro/acceleration finite vectors, optional battery 0–1, optional `extensions` object. Fields are defined but browser/native sensor capture is not implemented. Version changes require negotiation; new extensions must not alter baseline semantics.

## Heartbeat and shutdown

`{"type":"ping","timestamp":123}` → `{"type":"pong","timestamp":123}` once a second. RTT is measured on the originating clock. Linux resets/drops the virtual gamepad after six seconds without a frame, on malformed input, close, disconnect or Ctrl+C. SIGKILL/OS process teardown removes the uinput device; an explicit neutral frame cannot be guaranteed on forced kill.

`{"type":"disconnect"}` ends a session. Browser sends neutral input first when connected. Blur/hidden-tab/profile changes reset local inputs. Unexpected close retries at 1, 2 and 3 seconds, then requires manual reconnect. Every reconnect re-pairs; a rotated/expired PIN requires user entry. No insecure persistent trust credential is stored.

## Rate and telemetry

20–120 Hz configurable input sampling, default 60 Hz. Send changed state only; heartbeat independently keeps a held state alive. Native caps text frames at 4096 bytes and ~240 messages/sec. TCP/WebSocket is ordered/reliable: network packet loss is not inferred from frame count. `sent` counts controller snapshots, `received` counts validated native responses. PC incoming rate and local phone IP cannot be accurately obtained by the browser; do not invent them.

## Linux mapping

| Input                              | Linux event                       |
| ---------------------------------- | --------------------------------- |
| Left X/Y                           | ABS_X / ABS_Y, −32767…32767       |
| Right X/Y                          | ABS_RX / ABS_RY, −32767…32767     |
| L2 / R2                            | ABS_Z / ABS_RZ, 0…255             |
| D-pad                              | ABS_HAT0X / ABS_HAT0Y, −1…1       |
| Cross / Circle / Square / Triangle | BTN_SOUTH / EAST / WEST / NORTH   |
| L1 / R1                            | BTN_TL / BTN_TR                   |
| L3 / R3                            | BTN_THUMBL / BTN_THUMBR           |
| Create / Options / System          | BTN_SELECT / BTN_START / BTN_MODE |

This is an Xbox-style evdev device, not a claim of Linux XInput or Steam compatibility. Driver/Steam detection needs hardware verification.
